Design language

Desktop + Work popup

Folders sit in the icon column next to This PC. Hovered folder gets a frosted tile. Popup: large frosted panel, title row with expand and close, 4×2 grid of real app icons, page dots.

Glass folder icon

Blue-to-violet back plate with a frosted see-through front flap and soft glow. Becomes the default folder icon, recolourable per folder.

Start-menu panels

Tall glass panels, pill search box, segmented view switch, glass toggles. Pattern library for the Settings window.

3×4 icon grid

Rounded icon tiles; hover shows a lighter rounded plate behind the item. Used for item hover inside popups.

Radius 8 / 16 / 28 1px white rim at 22–35% Blue tint #3B6FE0 at 10–25% Segoe UI Variable Motion 120 / 200 / 320 ms
Architecture

Key technical decisions

AreaDecisionWhy
Desktop layerPrimary: each folder is a small borderless window owned by the desktop (Progman), kept at the bottom of the stack, hidden from taskbar and Alt-Tab. Fallback: child of the desktop icon view. Picked by PoC results, both behind one IDesktopHost interface.Stays under app windows, survives Win+D, never hides your real desktop icons, no "always on top" hack.
HostingOne small window per folder, not one full-screen overlay.A full-screen overlay would block desktop icon clicks.
GlassPopup and Settings use Windows' own Acrylic backdrop (DWM). Desktop tiles use a static gradient and rim, no live blur. Solid fallback when transparency is off.Windows does the blur on the GPU; nothing runs while idle.
Explorer watchTaskbarCreated message, a wait handle on the Explorer process, and a WinEvent hook on the desktop window. No polling.Event-driven, near-zero idle cost.
Monitor identityDisplay device path + EDID IDs from QueryDisplayConfig. Screen order is never saved.Screen order changes after reboot or reconnect.
PositionsStored per monitor as fractions of the work area plus DPI info, clamped on change.Survives resolution, scaling and rotation changes.
IconsShell image factory up to 256 px, cached as PNG on disk, loaded only when a popup opens.Real icons, including Store apps; fast reopen.
LaunchingOpens the original .lnk / .url when the item came from a shortcut; Store apps via shell:AppsFolder.Keeps arguments, working folder and run-as settings.
StorageJSON in %APPDATA%\GlassFolders, atomic writes, schema version + migrations, rolling backups.A crash mid-save can't corrupt your layout.
Tray & startupOwn tray icon wrapper, HKCU\…\Run with --tray, single-instance mutex.No admin rights, no Windows service.
DependenciesNone at runtime beyond .NET itself. xUnit for tests.Low memory, nothing extra to update.
Build sequence

Core desktop organizer

v0.2.0Size LSonnet 5.5 · high

  • Folder right-click menu (all 9 entries) and item menu. Lazy icon cache.

Tray, startup and Explorer recovery

v0.4.0Size MOpus 5.5 · high
  • Single instance; tray icon with the 7-item menu; no taskbar button.
  • Start with Windows, start in tray, optional delay, waits for the desktop shell.
  • Ordered clean exit that releases every hook, handle and the tray icon; intentional exit stops recovery.

Which model, which effort

Model recommendation

Switching per phase Opus 5.5 for phases 1, 3, 4, 5

Undocumented Windows behaviour, visual judgement, recovery race conditions and multi-monitor edge cases. Phase 1 at xhigh, the rest at high.

Switching per phase Sonnet 5.5 for phases 2, 6, 7, 8, 9

Well-specified, testable work. High effort for 2, 6 and 8; medium for 7 and 9. Move Phase 8 to Opus if a leak needs diagnosing.

Not switching Opus 5.5 at high throughout

Use xhigh for Phase 1 only. Run one session per phase; each starts by reading PLAN.md and DEVLOG.md.

Risks

What could go wrong

RiskLikelihoodMitigation
Desktop-owned window misbehaves on 25H2MediumFallback host tested in the PoC; z-order guard.
A Windows update changes the desktop layoutMediumAll undocumented code isolated in one host class; probe tool; documented in Known Issues.
Acrylic glitches in WPF (black flash, resize artefacts)MediumPre-create popup hidden; set backdrop before first show; solid fallback.
Memory over 100 MBLow–MediumLazy icons decoded at display size; release popup visuals when closed.
Can't test 2–3 monitors hereHighSimulated topology tests; virtual display driver or a second screen.
.NET runtime missing on another PCMediumInstaller checks and installs it, or ship self-contained.
Open questions

Decisions needed before building

D1

Multi-monitor testing. Use a virtual display driver for now, or will you test on a PC with more screens?

D2

Installer size. Recommended: small installer (~5 MB) that fetches .NET 10 if missing. Alternative: ~70 MB self-contained, no prerequisites.

D3

Desktop shortcut dropped into a folder. Leave the original on the desktop (brief default), or add an opt-in setting that moves it into GlassFolders storage?

D4

Branching. Recommended: one branch per phase, merged into main. Alternative: commit straight to main.

D5

License. MIT, all rights reserved, or something else?
